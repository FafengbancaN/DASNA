## 环境与验证边界

两个已有 Conda 环境的相关依赖已记录在 `environments/`，实测结果与重建限制见
[environment.md](environment.md)。本轮环境审查只做导入、依赖一致性及小型运算检查，
未训练模型，未执行论文复现实验。新的环境文件未经过全新机器安装验证。

检测环境的 CUDA/Mamba 小型前向通过；增强环境的 CPU 运算和小图分区通过，但其
PyTorch 2.6.0+cu124 不能在当前 RTX 5060 Ti 上执行 CUDA 内核。该限制已记录，
没有修改用户环境。

整理后的 `scripts/check_environment.py` 还在两个已有环境中分别完成生成端
CPU/METIS 检查与检测端 CUDA/Mamba 检查。该检查范围仍是环境能力验证。

## 旧缓存与方法待核对项

原有 `data/generated/` 中的 8 个 standalone 缓存保留原内容；检查发现其生成节点
标签均为 1。旧文件名中的增强比例按全图异常数计算，例如 Amazon 的 10% 对应
82 / 821，Questions 对应 146 / 1460，Weibo 对应 87 / 868。新增强入口的比例定义
以训练集异常节点数为基准。因此，旧缓存不符合新比例定义，不能仅凭文件名直接
作为新比例实验输入；用于比例比较前需要按同一数据划分和新定义重新生成。

本轮保留原有方法计算逻辑。另发现 residual 分支的训练 `score_diff` 计算恒为零，
而测试阶段使用首个邻居分数作为比较依据；这两处需要结合方法公式核对。本轮
没有以代码整理为由擅自修改这些科学计算，也未据此重新训练或评价模型。

## 运行接口与检查点变化

增强模块统一使用独立异常训练图输出，退役原有的合并原图导出分支。后者存在
跨批次索引、特征尺度和原图边保留问题，不能作为整理后的标准运行入口。现有数据
文件未重新生成；新输出默认拒绝覆盖已有 MAT 文件，可通过 `--output-dir` 分开保存。

新的增强检查点采用版本 1 的 `state_dict` 与模型结构、训练集归一化和输入签名
元数据，使用 `weights_only=True` 加载，避免跨入口与旧包名的整对象反序列化问题。
旧的整模型 pickle 检查点不能直接传给新入口 `--resume`，需要重训练或单独完成
显式迁移。本次提供的原始目录没有模型检查点，未执行旧权重迁移。

数据路径、缺失配置、YelpChi/Facebook 文件命名、生成节点 mask 重映射、Python
集合采样、空批次、单节点批次和训练损失日志等运行问题已处理。小型回归检查和
实测范围见 [validation.md](validation.md)。这些修复不代表论文结果已经重新验证。
